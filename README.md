# Турнирная Сетка — ASL Cup

Веб-приложение для создания и ведения спортивных турниров. Проект ориентирован на футбольные турниры ASL и предназначен прежде всего для организатора соревнований.

## Что уже работает

- список команд;
- добавление, редактирование и удаление команд;
- загрузка логотипов;
- выбор команд для текущего турнира;
- выбывание с посевом;
- выбывание со случайным распределением;
- первый раунд швейцарской системы;
- круговой турнир;
- ввод счёта матчей;
- автоматическое определение победителя по счёту;
- автоматическое продвижение победителя в следующую стадию;
- автоматическое прохождение bye;
- сохранение состояния в браузере;
- предустановленный список команд ASL.

## Как это работает

Основной сценарий:

1. Открыть приложение.
2. Выбрать команды.
3. Выбрать формат турнира.
4. Нажать **«Сгенерировать сетку»**.
5. Вводить счёт сыгранных матчей.
6. Победители автоматически переходят дальше.

Состояние сохраняется после каждого изменения, поэтому обычная перезагрузка страницы не должна удалять текущий турнир.

## Формат «Выбывание»

Для турнира на выбывание приложение автоматически рассчитывает размер сетки как ближайшую степень двойки.

Примеры:

| Команд | Размер сетки | Раунды до финала |
|---:|---:|---:|
| 2 | 2 | 1 |
| 4 | 4 | 2 |
| 8 | 8 | 3 |
| 16 | 16 | 4 |
| 32 | 32 | 5 |
| 37 | 64 | 6 |

Когда участников меньше, чем мест в сетке, свободные места становятся **bye**. Команда с bye проходит дальше без игры.

Сетка визуально строится зеркально:

\`\`\`text
ЛЕВАЯ ЧАСТЬ → ПОЛУФИНАЛ → ФИНАЛ ← ПОЛУФИНАЛ ← ПРАВАЯ ЧАСТЬ
\`\`\`

## Посев и случайное распределение

### Посев

Выбранные команды используются в том порядке, в котором они находятся в списке.

### Случайный режим

Перед построением сетки команды перемешиваются алгоритмом Fisher–Yates.

Важно: текущий режим «Посев» не содержит отдельного менеджера рейтинга или номера посева. Для сложного официального посева это отдельная задача.

## Счёт и продвижение

Когда у матча есть две команды и оба счёта заполнены:

- больший счёт определяет победителя;
- победитель автоматически передаётся дальше;
- его прошлый счёт не переносится в новый матч;
- при изменении результата старый победитель в следующих раундах очищается и пересчитывается.

### Ничья

В матче на выбывание ничья не назначает победителя автоматически.

Это сделано намеренно: для футбола после ничьей может действовать разный регламент:

- дополнительное время;
- серия пенальти;
- ручное назначение победителя.

Сейчас эти правила ещё не заведены в отдельную настройку.

## Швейцарская система

Текущая версия создаёт **первый раунд** пар.

Полноценный швейцарский турнир требует дополнительной логики:

- расчёта очков;
- распределения по результатам;
- истории соперников;
- запрета повторных встреч;
- правил bye;
- тай-брейков.

Эта логика пока не притворяется реализованной.

## Круговой турнир

Каждая команда получает одну пару с каждой другой командой.

Количество матчей:

\`\`\`text
N × (N - 1) / 2
\`\`\`

Например:

- 4 команды → 6 матчей;
- 8 команд → 28 матчей;
- 10 команд → 45 матчей.

Сейчас генерируется список матчей. Полноценная турнирная таблица с очками, разницей мячей и местами — следующий этап развития.

## Сохранение данных

Текущая версия использует:

\`\`\`text
Browser
   ↓
localStorage
   ↓
tournament-bracket-data
\`\`\`

В localStorage сохраняются:

- команды;
- логотипы;
- выбранные команды;
- текущий формат;
- созданные матчи;
- счёт;
- победители.

Логотипы сохраняются как data URL / Base64.

### Ограничение

Данные локальные.

Это значит:

- другой компьютер не увидит этот турнир;
- телефон не синхронизируется автоматически;
- очистка данных сайта браузером может удалить сохранённое состояние.

Отображение:

- карточек матчей;

Серверная часть пока не используется для хранения турнира.

## Cloudflare и база данных

В репозитории уже есть конфигурация Cloudflare Workers и D1, однако **турнирные данные сейчас туда не сохраняются**.

Текущая архитектура:

\`\`\`text
React
  ↓
tournament-store
  ↓
localStorage
\`\`\`

Подготовленная серверная архитектура:

\`\`\`text
React
  ↓
Hono API
  ↓
Cloudflare Worker
  ↓
D1 / R2
\`\`\`

Переход на серверное хранение имеет смысл, когда понадобится:

- работа с нескольких устройств;
- общий доступ организаторов;
- несколько турниров одновременно;
- публичная страница турнира;
- API для трансляции;
- резервное хранение.

## План развития

Следующими логичными этапами являются:

### Этап 1 — правила турнира

- дополнительное время;
- пенальти;
- ручной выбор победителя;
- полноценные bye;
- явный номер посева.

### Этап 2 — таблицы

- турнирная таблица;
- очки;
- победы/ничьи/поражения;
- забитые и пропущенные мячи;
- разница мячей;
- тай-брейки.

### Этап 3 — полноценная швейцарская система

- несколько раундов;
- автоматические пары;
- учёт истории соперников;
- автоматический bye;
- итоговое ранжирование.

### Этап 4 — сервер

- D1;
- API;
- авторизация;
- несколько турниров;
- резервное хранение.

### Этап 5 — трансляция

После появления стабильного API данные турнира можно отдавать отдельному broadcast-слою:

\`\`\`text
Турнирная Сетка
      ↓ API
Broadcast Overlay
      ↓
OBS / vMix / NodeCG
      ↓
YouTube / Telegram / другие платформы
\`\`\`

Это позволит использовать счёт и составы из одной системы одновременно в интерфейсе организатора и в графике трансляции.
